Support 13: proof-producing continuation
======================================

The complete marked support catalogue has 55 cases. The distinguished
residue 0 carries a largest fibre, with ties allowed. A certificate for a
case and interval [l,u] excludes total size at most 93 and largest fibre
in that interval in either ring. It is not an exclusion of all choices of
largest vertex on an unmarked affine support unless those other marked
cases are separately covered.

The Round 6 case Tmask37848950 is inherited once. Baseline cases use the
frozen Round 6 joint encoder. The aggregate replay can also ingest the
explicitly whitelisted common-ring variants baseline, span, span4, dense,
plane and combined from Round 7 variant_trials.py. Each variant's complete
semantic source dictionary must match its production hashes, and the
replay regenerates that exact variant formula. Its added mathematical
lemmas remain separate soundness obligations. No new exact-ring encoder
is automatically included; a certificate for one ring alone cannot close
a common-ring case or band.

Source hashes, exact formula bytes, solver
output and original DRAT bytes are bound in each completed receipt. Only
the mandatory pinned CakeML result establishes CNF unsatisfiability; the
solver itself and DRAT-to-LRAT conversion need not be trusted.

The current count is in SUPPORT13_CERTIFICATE_MANIFEST.json and the fresh
SUPPORT13_FULL_REPLAY.json receipt. Treat a manifest as an inventory, not
as a substitute for proof checking. A temporary quick receipt covers only
its explicitly listed samples. Timeouts, resource stops and incomplete
proof streams contribute no exclusion credit.

The compact checkpoint distribution replaces original full search traces
with complete, freshly checked DRAT cores. Its portable entry point is:

    python3 research_round7/compact_support13/verify_compact_support13.py

That replay binds its core inventory to this directory's original
certificate manifest, regenerates every original CNF exactly, and checks
each replacement proof against that unchanged CNF. Original full DRAT
payloads are not needed for the compact route. Mathematical coverage is
unchanged by proof trimming because every replacement is checked anew.

When original full proof payloads are present, this directory also offers
their independent replay, without running a SAT search:

    python3 research_round7/support13/verify_support13.py

The replay requires Python 3.10+, a C compiler, Linux x86-64 and temporary
disk space for LRAT reconstruction. All checker sources are bundled in
the earlier Round 5 dependency. No network or PySAT installation is used.
Every CNF is regenerated byte-identically from its declared support and
maximum interval. Every stored and decoded certificate hash is checked,
the pinned checkers are rebuilt, and CakeML must accept the proof against
that same CNF. Persisted inputs are rehashed after checking.

For development only, snapshot completed immutable case receipts first:

    python3 research_round7/support13/verify_support13.py --freeze

Do not freeze after arbitrary modifications and interpret a successful
hash calculation as a mathematical validation. The frozen encoder and
catalogue have explicit expected hashes. Mathematical soundness of the
encoder and completeness of its finite data retain the documented Round 6
one-way audit obligations; this replay does not formalize them.

An example bounded search command is:

    python3 research_round7/support13/certify_support13.py --limit 30

It uses a local CaDiCaL binary, whose hash is recorded. Override --solver
to use another executable. The search tool is not part of the trusted
replay. One solver runs at a time. Live proof files remain in a private
temporary directory, with a wall-clock, proof-size and free-disk guard.
Unaccepted traces are hashed and discarded; no incomplete proof is sold
as a certificate. Completed compressed artifacts are copied and hashed
before publication. Existing case directories are never overwritten.

Hard joint cases can be split exhaustively, for example [2,14], [15,16],
[17,18]. Each interval is a different exact CNF and requires its own
accepted proof. Use --lower, --upper, --mask and a distinct --tag. The
manifest computes the union of checked maxima for each case, so an open
interval prevents a joint-case exclusion. Overlapping branches do not
increase the case count. Covering all 55 marked cases is necessary before
this collection alone can exclude support 13 for every maximum2..18.

The manifest also reports certified marked-case counts at each exact
maximum. A maximum cell closes only when all 55 marked cases are covered
at that value. This permits a complete upper band [17,18] to yield a global
support13 exclusion at those maxima even while lower maxima remain open.
The queue planner lists unproved branch jobs; its output is not a proof:

    python3 research_round7/support13/plan_bands.py --refresh

A separate maximum11 ledger uses the inherited Round6 reduction to four
open support13 affine classes, comprising14 marked roles. It subtracts a
class from the inherited total46 only when every possible largest-vertex
role in that class has a checked maximum11 certificate. This dependency
is named and hashed; it never counts the inherited excluded classes as
newly certified marked cases and never subtracts middle weight profiles.

The optional RUP-unit search wrapper is documented in
RUP_UNIT_SEARCH_NOTE.txt. It supplies a proof prefix checked against the
unchanged original CNF. Its finite proof-plumbing controls replay without
a SAT solver using verify_rup_unit_controls.py --replay. The current search
producer stops whole process groups and reaps wrapper descendants before
publishing any file; verify_process_supervision.py exercises those guards.

Creating STOP_REQUESTED in this directory requests a clean stop between
cases. It does not interrupt a proof checker or turn a partial case into
an accepted one. Remove that file before intentionally resuming searches.

No proof-free historical timing row is counted here. No scalar profile
count is subtracted merely because some marked support cases are closed.
